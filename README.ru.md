# РЕДУТ/1 (Redoubt/1) — защищённый канал управления для ПЛК

[English](README.md) · **Русский**

Редут — полевая крепость, которую держат изнутри. Здесь это протокол и библиотека, которые стоят
между сетью АСУ ТП и контроллером и решают **по operation**, а не по соединению: прошёл ли запрос.

## Зачем

Modbus не умеет ни аутентификации, ни авторизации, ни защиты от повторов. TLS-профиль Modbus
Security закрывает **канал**, но любой аутентифицированный клиент по-прежнему может вызвать любую
функцию. FrostyGoop (2024) говорил по Modbus/TCP прямо в процесс; AA26-097A (2026) описывал атаки
на ПЛК через интернет, подмену файлов проектов и данных HMI. Отсюда семь ворот, которые проходит
каждый запрос, и восьмые — по таймеру.

## Семь ворот

1. **кадр** — аутентифицируется и разбирается ровно в одну известную операцию (AEAD по заголовку);
2. **сессия** — кадр принадлежит открытой сессии;
3. **повтор** — номер свежий с учётом 64-широкого окна и **счётчика загрузок, переживающего сброс**;
4. **политика** — deny-overrides, по умолчанию запрет: функция, диапазон, unit, роль;
5. **двойное управление** — для опасных выходов две подписи двумя разными ключами;
6. **журнал** — если запись в аудит-цепочку не удалась, операция **не выполняется**;
7. **применение** — запись журналируется со старыми значениями, поэтому пачку можно отменить.

Восьмые ворота — таймер «мёртвой руки»: если супервизор замолчал, все выходы, для которых задано
безопасное значение, переводятся в него, и это записывается.

| проверка | результат |
|---|---|

| `cargo clippy --all-targets -- -D warnings` | чисто |

Паритет с эталоном нашёл **две настоящие ошибки**: пролог смешивался в транскрипт двумя кусками
вместо одного, и pre-message открытые ключи не подмешивались вовсе. Обе исправлены, тест
`tests/snow_parity.rs` теперь их ловит.

## Чего это не делает

Не заменяет сегментацию; не спасает от проекта, подписанного самим инженером; не обещает
конфиденциальность на 9600 бод; не защищает от вредоносной прошивки ПЛК; не заменяет управление
ключами; сторож — единая точка отказа, поэтому их два и они должны согласиться. Полный список —
в [SECURITY.md](SECURITY.md).

## RS-485 / Modbus RTU: южная сторона

Настоящие заводы — это RS-485-линии, не только IP. `src/rtu.rs` говорит по Modbus RTU
южнее редута: один ADU на входе — ровно одна операция на выходе, и судит её **та же**
машина правил (второго языка авторизации для второго транспорта нет). Разборщик
отказывает, а не угадывает: лишние байты (`TrailingBytes` — линк-слой режет по тишине,
а не по «второму CRC»), нулевой unit (`BroadcastUnit` — «всем» не бывает субъектом
авторизации), запись в катушку не `0x0000`/`0xFF00` (`BadValue`), диапазон через
`0xFFFF` (`AddressWrap`) и всё длиннее 256 байт (`TooLong` — отказ, а не усечение).

В модели прибавилось пять теорем: провал CRC не становится операцией; пересекающий
пространство регистров диапазон не разбирается; broadcast не разбирается; разбор —
обратная сборке; успех фиксирует длину кадра как ровно один ADU своей функции.
Опорные кадры из спецификации Modbus over serial line (`01 03 00 00 00 01 84 0A`,
`11 03 00 6B 00 03 76 87`) — юнит-тесты.

Чего в библиотеке сознательно **нет**: COM-портов, скорости и таймера тишины в 3,5
символа — это слой линка над проводом. Северная сторона остаётся Redoubt/1 по IP:
на 9600 бод один кадр ~100 байт стоит около секунды линии — не тот бюджет для
врат сердцебиения.

## Начать

```sh
cargo test                    # 28 тестов
ci/run.sh                     # то же, что CI: fmt, clippy, tests, lean
lean lean/Redoubt.lean        # доказательства (нужен Lean 4)
```

Политика — текстовый файл, `policy.example` рядом.
